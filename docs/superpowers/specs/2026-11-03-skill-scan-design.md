# 스킬 스캔 설계 (feat/skill-scan)

## 목적

README 로드맵 1단계. 내 컴퓨터에 설치된 Claude Code 스킬을 찾아, `SKILL.md`에 적힌 이름·설명·출처를 목록과 상세 화면으로 보여준다. 이후 단계(요약, 사용 현황, 삭제, 배포)는 모두 이 스캔 결과를 바탕으로 한다.

성공 기준: 첫 스캔에서 찾은 스킬마다 이름·출처·설명이 보이거나, 보이지 않으면 그 이유가 보인다 (README "핵심 지표" 첫 항목).

## 범위

**포함**
- Claude Code 전역 스킬: `~/.claude/skills/<이름>/SKILL.md`
- Claude Code 플러그인 스킬: `~/.claude/plugins/installed_plugins.json`의 각 `installPath` 아래 `skills/<이름>/SKILL.md`
- 리퀴드 글래스 목록 화면과 상세 화면
- macOS, Windows

**제외 (다음 단계로)**
- 프로젝트 스킬 (`<project>/.claude/skills`). 다음 브랜치에서 한다.
- Codex·`~/.agents/skills`를 에이전트로 다루는 일 (로드맵 4단계)
- 한국어 요약·카테고리, 사용 횟수·마지막 사용일 (2단계)
- 메모, 비활성화, 삭제, 배포 버튼 (3·4단계)
- 검색

**하지 말 것**
- 스캔 중 사용자 파일을 쓰거나 바꾸지 않는다. 이번 기능은 읽기만 한다.
- 읽지 못한 스킬을 목록에서 빼지 않는다 (README "실패한 항목은 숨기지 않는다").
- 캐시에 남은 플러그인 옛 버전을 설치된 스킬처럼 보여주지 않는다.

## 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 플러그인 버전 | `installed_plugins.json`의 `installPath`만 | 캐시 폴더에는 옛 버전이 남아 있다 |
| 머리말 파싱 | `yaml` 패키지 추가 (Dart 공식) | 여러 줄 `description`(`>`, `|`)과 따옴표를 정확히 읽는다 |
| macOS 샌드박스 | 유지 | 사용자 결정 |
| macOS 폴더 권한 | `file_selector`(Flutter 공식)로 폴더 선택 + 북마크 저장·복원은 `macos/Runner`에 Swift로 직접 작성 | 개인 관리 패키지에 파일 권한 코드를 맡기지 않는다 |
| 링크 스킬 | "읽을 수 없음, 폴더 권한 필요"로 표시하고 그 폴더를 추가로 허락하는 버튼 제공 | 전역 스킬 일부가 `~/.agents/skills`를 가리키는 링크다 |
| Windows | 폴더 선택 없이 `%USERPROFILE%\.claude`를 바로 스캔 | Windows에는 샌드박스가 없다 |
| `skills/synced/` | 펼치지 않고 항목 하나로 표시 | 사용자 결정. claude.ai 계정에서 동기화된 스킬이 `synced/<계정ID>/<스킬>/`에 들어 있다 |
| 꺼진 플러그인 | 목록에 넣고 "꺼짐" 표시, 사이드바 "꺼짐" 필터 | 사용자 결정. 켜짐 여부는 `~/.claude/settings.json`의 `enabledPlugins` |
| 프로젝트 범위 플러그인 | 포함하고 카드에 프로젝트 경로 표시 | 사용자 결정. 설치 파일은 `~/.claude/plugins/cache`에 있어 읽을 수 있다 |
| 플러그인 옛 버전 | 목록에는 넣지 않고 "옛 버전 폴더 N개가 남아 있습니다" 알림만 | 사용자 결정 |
| 플러그인 묶기 | 출처 태그만 (플러그인별 필터 없음) | 사용자 결정 |

추가 패키지: `yaml`, `file_selector`. 둘 다 공식 패키지다.

## 접근 방식 (고려한 것)

**폴더 권한 유지**
1. `file_selector` + Swift 직접 작성 (선택). 외부 패키지가 하나만 늘고, 권한 코드가 우리 저장소에 있다.
2. `file_selector` + `macos_secure_bookmarks`. 직접 짜는 코드는 적지만 개인 관리 패키지에 의존한다.
3. 저장하지 않음. 앱을 켤 때마다 폴더를 다시 골라야 한다.

**샌드박스**
1. 끄기. entitlements 한 줄로 끝나지만 Mac App Store 배포가 막힌다.
2. 유지 (선택). 폴더 선택과 북마크가 필요하다.

## 동작

### macOS 권한 흐름
1. 앱을 시작하면 저장된 북마크를 복원한다. 북마크가 유효하면 바로 스캔한다.
2. 북마크가 없거나 깨졌으면 "Claude Code 스킬 폴더 허락" 화면을 보여준다. 버튼을 누르면 `~/.claude`에서 시작하는 폴더 선택 창을 연다. 숨김 폴더라서 안내 문구를 함께 보여준다.
3. 사용자가 고른 폴더가 `.claude`가 아니면 (`skills/`도 `plugins/`도 없으면) 다시 고르라고 안내한다.
4. 링크 스킬의 실제 위치가 허락 범위 밖이면 해당 항목에 "폴더 추가 허락" 버튼을 둔다. 고른 폴더도 북마크로 저장하고 다시 스캔한다.
5. 필요한 entitlements: `com.apple.security.files.user-selected.read-only`, `com.apple.security.files.bookmarks.app-scope`. DebugProfile와 Release 둘 다 넣는다.

샌드박스 앱에서는 Dart의 `HOME`이 앱 컨테이너 경로를 가리킨다. 실제 홈 경로(폴더 선택 창의 시작 위치)는 Swift에서 얻는다.

### 스캔
- 전역: `<claude>/skills/` 아래 각 항목(폴더 또는 폴더 링크)에서 `SKILL.md`를 찾는다.
- 전역 중 `synced/`는 펼치지 않는다. 문제 카드가 아니라 "동기화" 출처의 항목 하나로 보여준다. 설명은 "claude.ai에서 동기화된 스킬 폴더"로 하고, 상세에서는 파일 목록을 보여준다.
- 플러그인: `installed_plugins.json`의 모든 항목(scope 무관)을 본다. user 범위는 `settings.json`의 `enabledPlugins`로 켜짐/꺼짐을 정한다. 프로젝트 범위 항목은 그 프로젝트의 설정 파일을 읽을 수 없으므로(샌드박스) 켜짐 여부를 "모름"으로 두고, 항목의 프로젝트 경로를 표시한다. 프로젝트 경로 필드 이름은 실제 데이터로 아직 확인하지 못했다(현재 기기에는 user 항목만 있음). 플러그인마다 `installPath/skills/` 아래 각 폴더를 본다. `skills/`가 없는 플러그인은 스킬 0개로 보고 오류로 치지 않는다. `settings.json`을 읽지 못하면 켜짐 여부를 "모름"으로 두고, 목록 위에 그 사실을 표시한다.
- 옛 버전: `installPath`의 상위 폴더(`cache/<마켓>/<플러그인>/`)에서 현재 버전이 아닌 폴더 수를 세어 알림으로만 보여준다.
- 스킬 하나마다 다음을 만든다.
  - 이름 (머리말 `name`, 없으면 폴더 이름)
  - 설명 (머리말 `description`)
  - 출처: 전역, 또는 플러그인 `<플러그인>@<마켓>` + 버전
  - 폴더 경로, 링크라면 실제 경로
  - `SKILL.md` 원문
  - 폴더 안 파일 목록 (상대 경로)
  - 상태: 정상, 또는 문제와 그 이유
- 문제로 표시하는 경우: `SKILL.md` 없음, 머리말 형식 오류, 권한 없음, 깨진 링크, `installed_plugins.json` 읽기 실패.
- 같은 이름이 전역과 플러그인에 모두 있으면 둘 다 보여주고 출처로 구분한다.

### 목록 화면
시안 "스킬 목록"(https://claude.ai/artifact/STvot9BocgrsUZXwDAWF9f)을 따르되 이번 범위만 넣는다.
- 사이드바: Claude Code 하나와 개수, 그 아래 "전체 / 전역 / 플러그인 / 꺼짐" 필터
- 툴바: "다시 스캔" 버튼
- 카드: 이름, 출처 태그, 설명(몇 줄까지만), 문제가 있으면 이유
- 문제 있는 스킬도 카드로 보여준다.

### 상세 화면
시안 "스킬 상세"에서 이번 범위만 넣는다.
- 뒤로 가기, 이름, 출처 태그, 경로
- 설명
- `SKILL.md` 원문
- 포함된 파일 목록
- 문제가 있으면 이유와 해결 방법 (예: 폴더 추가 허락)

### 디자인
- 앱 안에 그라데이션 배경을 깔고, 그 위의 사이드바·툴바는 `BackdropFilter` 블러로 만든다. 창 자체를 반투명하게 만드는 패키지는 쓰지 않는다.
- 카드는 불투명하게 둔다.
- macOS "투명도 줄이기"가 켜져 있으면 블러 대신 불투명 배경을 쓴다. 이 설정값은 같은 Swift 채널에서 읽는다. Windows에서는 블러를 그대로 쓴다.

## 빌더에게 맡기는 것
- 폴더·파일 구조와 상태 관리 방식 (패키지 추가 없이)
- 카드 그리드 크기, 간격 등 세부 수치 (시안 참고)
- 파일 목록이 너무 길 때의 처리
